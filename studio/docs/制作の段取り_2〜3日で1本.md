# 制作の段取り：2〜3日で1本

プリプロ（設定・舞台・キャラの参照画像・Blender の舞台）を除いて、**1話（約3分）を2〜3日**で作る。
そのために、エージェントが作って自分でレビューし、監督は**5回の関門だけ高い位置から見る**。生成の使用量は**安い工程で詰めてから高い工程へ**進めて抑える。

## 1. 1話の物量の目安（3分）

| 項目 | 目安 | 根拠 |
| --- | --- | --- |
| 尺 | 180秒（話によって前後） | |
| コマ | 約110 | EP09 4分版は 255秒で162コマ（1コマ平均1.6秒） |
| 9コマシート | 約13枚 | 110 ÷ 9 |
| 動かすカット（動画生成） | 30〜35 | カメラワーク・芝居のあるカットだけ。残りは静止＋編集の小さな拡大縮小 |
| 台詞（仮の声） | 60〜80行 | |
| 効果音・劇伴 | 効果音 15〜20、劇伴 2〜3曲 | |

## 2. 3日の流れと関門

```
        エージェント（自動で進む）                     監督（関門だけ）
Day1 午前  脚本を読む → 設計（シーン・尺・動線・小物）
                     → セルフレビュー（尺の合計、正本との矛盾）  ──▶ G1 設計    30分
Day1 午後  字コンテ（1コマ1行）→ セルフレビュー
                     → Blender で背景をレンダー（カメラ位置ごと）  ──▶ G2 字コンテ 30〜45分
Day1 夜    9コマシートを全部生成 → コマに切り出す
           → セルフレビュー（シート単位）→ だめなコマだけ作り直し（上限2回）
Day2 午前                                                       ──▶ G3 画     60分
           （「AIが通したもの」を流し見、「AIが止めたもの」に判断）
Day2 午後  指摘の直し → 動かすカットだけ動画生成 → 仮の声・効果音・劇伴
Day2 夜    ラフ編集（ツールの編集画面で通し）→ セルフレビュー（尺・つなぎ）
Day3 午前                                                       ──▶ G4 ラフ通し 30分
Day3 午後  直し → Premiere 用 XML → Premiere / After Effects で仕上げ ─▶ G5 仕上げ 30分
```

- 監督の時間は1話で**約3〜4時間**。それ以外の時間、エージェントは関門の承認を待たずに進められるところまで進める（例：G1 の承認後、字コンテと背景レンダーは並行）。
- 2日で終える話は、Day1 夜の生成を早めに回し、G3 と G4 を Day2 の中で行う。
- 各関門の判断は「この設計でいく」「直してほしい」「AIが通したもの：良い／採用」の短い操作で済むようにしてある。直しの文章は、気になるものにだけ書く。

## 3. レビューの分担：AIが全部見て、監督は上から見る

| 誰が | 何を | どこで |
| --- | --- | --- |
| エージェント | **全部**のテイクを観点ごとに自分で見る（意図・配置と左右・芝居・キャラ崩れ・光と色・つなぎ）。芝居はキャラの性格・テンションと芝居の辞書（`06_設定/キャラ`）で照らす | `self-review` |
| エージェント | 不合格は自分で作り直す。人のレビューなしの作り直しは**1コマ2回まで** | 上限を超えると生成が止まる |
| 監督 | **AIが通したもの**を流し見（1枚数秒）。良ければ「良い」「採用」、気になるものだけ開いて直しを書く | 画面「AIが通したもの」 |
| 監督 | **AIが止めたもの**（上限を超えて迷っているもの）に方向を出す | 画面「レビュー → AIが止めたもの」 |
| 監督 | 迷ったら**並べて比較**し、観点ごとの勝ちと理由を残す。これがいちばん強くエージェントに効く | 画面「並べて比較」 |
| エージェント | 監督の指摘が同じ種類で2回続いたら、ルールを提案。承認されたものが全話のブリーフに入る | 画面「ルール」 |

AIのセルフレビューは、監督のレビューと同じ形（観点タグ・範囲・コメント）で残すので、**AIの見立てと監督の見立てのずれ**が並んで見える。ずれが多い観点は、セルフレビューの基準（キャラのノートの「追記」やルール）を足して詰める。

## 4. 使用量を抑える仕組み

**安い順に確かめる。** 高い生成ほど後ろに置き、前の工程で方向を固めてから進む。

| 段 | 使うもの | 費用 | ここで決めること |
| --- | --- | --- | --- |
| 1 | 文章（設計・字コンテ） | 小（LLM のみ） | 尺、動線、画面配置、芝居、感情 |
| 2 | Blender の背景 | 0（自分の PC） | どこから何を撮るか、背景の量と配置 |
| 3 | 9コマシート | 中（1回で9コマ） | 構図・芝居・表情 |
| 4 | 単コマの作り直し | 中 | だめなコマだけ |
| 5 | 動画 | 大 | G3 で採用が決まったカットだけ |
| 6 | 声・効果音・劇伴 | 小〜中 | 仮。後で有料の音源や声優に差し替える |

ツールに入っている歯止め：

- **予算**：話数ごとにクレジットの予算を入れると、超える生成は止まり、優先するコマを監督に確認する。1回あたりの目安は `config.COST_TABLE`（仮の値。実際の単価に直す）。
- **作り直しの上限**：レビューなしで同じコマを3回作ったら止まる（`TSUKI_MAX_RETRIES`）。迷い続けて使い切るのを防ぐ。
- **動画は最後**：動画生成は G3 の後、採用されたコマだけに回す（手順で固定）。
- **LLM の使用量**：ブリーフは要点だけ（読むべきファイルの場所を示し、全文は貼らない）。セルフレビューはシート単位（9コマまとめて1回）。設計と字コンテは上位のモデル、セルフレビューの一次確認は軽いモデルのサブエージェントに回す。

1話の目安回数（作り直し率を含む）：シート 13×1.5 ≒ 20回、単コマの直し 約20回、動画 35×1.3 ≒ 45回、声 70行、効果音 20、劇伴 3。ここに実際の単価をかけたものを予算の初期値にする。EP の実績が出たら、`usage` から実際の値に直す。

## 5. 編集：ツールの中で、エージェントの操作を見ながら

- **ラフ編集はツールの中**（画面「編集（ライブ）」）：採用テイクを上映順に通しで再生し、台詞を字幕で出す。エージェントの操作（テイク作成、セルフレビュー、手直し）は右側に**リアルタイムで流れ**、触ったコマがタイムライン上で光る。監督はその場で尺・台詞・編集メモを手直しできる。
- **仕上げは Premiere / After Effects**：ツールから XML を書き出して読み込む。After Effects はカメラワーク（T.U./T.B.、パン）や黒板・メモの文字合成をスクリプト（ExtendScript）で組む。
- **次の段階（提案）**：Premiere の拡張パネル（UXP）に月灯スタジオの画面を入れる。そうするとツールが Premiere の中に嵌め込まれ、エージェントの編集操作（クリップの差し替え、尺の変更）をパネル経由で Premiere に直接反映し、その様子を Premiere の画面で見ながら監督も手で直せる。Codex のように別ウィンドウでアプリを操作させる形（画面操作）も可能だが、遅くて壊れやすいので、API で操作して画面で見せる形を先にする。

## 6. 背景：Blender からエージェントがレンダー

- 舞台の .blend に、カメラ位置ごとのカメラ（`CAM_A`〜`CAM_F`、シーン専用は `CAM_S1_xx`）を置く。
- エージェントは字コンテのカメラ位置から、`bg-render` でレンダーする。出力は背景 PNG と、カメラの位置・向き・焦点距離・**画面に映っている物と位置**の JSON。
- JSON はプロンプトの「どこから何を撮っているか」を書く手がかりになり、背景はシートの参照画像（@image1）になる。これで構図と配置の崩れ（4話の立ち位置、6話のレモン）を生成の前に防ぐ。

## 7. 脚本が変わったとき

脚本は仮で、変わる前提。設計と字コンテは脚本の版にひもづけ、脚本が変わったら、エージェントが差分を読んで**影響のあるシーンとコマだけ**を挙げ、そこだけ作り直す（未実装・次の段階）。採用済みのコマは、影響がなければそのまま残す。

## 8. サービス

| サービス | 使い方 | 状態 |
| --- | --- | --- |
| HAMSTER | シート・画像・動画 | **保留**（このクラウド環境では未接続。後で接続） |
| Runway | 仮の声・効果音・劇伴（画像・動画も可） | 実装あり・未検証。劇伴を Runway で作れるかは要確認 |
| Blender | 背景 | `bg-render`（ローカル PC で動かす） |
| Seedance / ComfyUI | 動画・画像 | 画面から手で足す |
