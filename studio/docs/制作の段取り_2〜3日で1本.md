# 制作の段取り：2〜3日で1本

プリプロ（設定・舞台・キャラの参照画像・Blender の舞台）を除いて、**1話（約3分）を2〜3日**で作る。
そのために、エージェントが作って自分でレビューし、監督は**5回の関門だけ高い位置から見る**。生成の使用量は**安い工程で詰めてから高い工程へ**進めて抑える。

## 0. 生成の方式（2026-10-19 決定）

- **開始フレームを使わない。** キャラの設定資料（1人1枚）・Blender の背景・配置図・必要な小物を参照画像（最大10枚）として渡し、立ち位置・向き・芝居はプロンプトで制御する。
- **Seedance 2.5（HAMSTER 経由）。** 1本最大30秒。プロンプトどおりに動くので、秒数と動きを細かく書く（[Seedance2.5_プロンプトの書き方](Seedance2.5_プロンプトの書き方.md)）。
- **生成の単位はショット（マルチショット）。** 字コンテと仮Vコンを並べて、1本で出した方がつながるかたまり（物を落として拾う、など）を1本にまとめる。
- **9コマの仮Vコンを、ドラフトの前の確認段にする。** エージェントがどんなカットを想像しているかを、安い画像で監督と確かめる。
- **480p ドラフトを全部出し切って映像にしてから判断する。** 採用したドラフトを入力に、1080p の本番へ順に変換する（入力動画をそのまま大きく作り直す）。

```
字コンテ ─▶ 9コマ仮Vコン（G2）─▶ ショット分け ─▶ 480p ドラフトを全部 ─▶ つないで通し（G3：採用／不採用）
                                                       ▲ 不採用は直して出し直す        │ 採用
                                                       └──────────────────────────────┘
                                                                     1080p 本番へ順に変換（promote-all）─▶ 仕上げ（G4・G5）
```

## 1. 1話の物量の目安（3分）

| 項目 | 目安 | 根拠 |
| --- | --- | --- |
| 尺 | 180秒（話によって前後） | |
| コマ | 約110 | EP09 4分版は 255秒で162コマ（1コマ平均1.6秒） |
| 9コマ仮Vコン | 約13枚 | 110 ÷ 9 |
| ショット（動画） | 約15〜20本 | 1本 10〜15秒が目安（最大30秒） |
| 480p ドラフト | 合計 約270秒 | 作り直し率 1.5 |
| 1080p 本番 | 合計 約200秒 | 採用したドラフトだけ。作り直し率 1.1 |
| 台詞（仮の声） | 60〜80行 | |
| 効果音・劇伴 | 効果音 15〜20、劇伴 2〜3曲 | |

## 2. 3日の流れと関門

```
        エージェント（自動で進む）                     監督（関門だけ）
Day1 午前  脚本を読む → シーン整理（変化 前→後・きっかけ・キャラごとの したい／する／内心・区切り）＋設計（尺・動線・小物）
                     → セルフレビュー（尺の合計、正本との矛盾）  ──▶ G1 シーン整理    30分
Day1 午後  字コンテ（1コマ1行）→ Blender で背景をレンダー（カメラ位置ごと）
           → 9コマの仮Vコン（約13枚）→ 切り出して通しで並べる
           → セルフレビュー                                       ──▶ G2 字コンテ＋仮Vコン 45分
Day1 夜    ショット分け（shot-plan → 並べて見て shot-set）
           → ショットごとに Seedance のプロンプトを仕上げ → 480p ドラフトを全部
           → セルフレビュー → だめなものだけ作り直し（上限2回）
           → ドラフトをつないだ通し（仮の声・効果音つき）
Day2 午前                                                       ──▶ G3 ドラフト通し 60分
           （通しで見て採用／不採用。「AIが止めたもの」に判断）
Day2 午後  不採用の直し（ドラフトで）→ 採用から順に 1080p 本番へ（promote-all）
Day2 夜    本番に差し替えた通し → セルフレビュー（ドラフトとの差、尺・つなぎ）
Day3 午前                                                       ──▶ G4 ラフ通し 30分
Day3 午後  直し → Premiere 用 XML → Premiere / After Effects で仕上げ ─▶ G5 仕上げ 30分
```

- 監督の時間は1話で**約3〜4時間**。それ以外の時間、エージェントは関門の承認を待たずに進められるところまで進める（例：G1 の承認後、字コンテと背景レンダーは並行）。
- 2日で終える話は、Day1 夜の生成を早めに回し、G3 と G4 を Day2 の中で行う。
- 各関門の判断は「この設計でいく」「直してほしい」「AIが通したもの：良い／採用」の短い操作で済むようにしてある。直しの文章は、気になるものにだけ書く。

## 3. レビューの分担：AIが全部見て、監督は上から見る

| 誰が | 何を | どこで |
| --- | --- | --- |
| エージェント | **全部**のテイクを観点ごとに自分で見る（意図・配置と左右・芝居・キャラ崩れ・光と色・つなぎ）。芝居はキャラの性格・テンションと芝居の辞書（`06_設定/キャラ`）で照らす | `self-review` |
| エージェント | 不合格は自分で作り直す。人のレビューなしの作り直しは**1コマ2回まで** | 上限を超えると生成が止まる |
| 監督 | **AIが通したもの**を流し見（1枚数秒）。良ければ「良い」「採用」、気になるものだけ開いて直しを書く | 画面「AIが通したもの」 |
| 監督 | **AIが止めたもの**（上限を超えて迷っているもの）に方向を出す | 画面「レビュー → AIが止めたもの」 |
| 監督 | 迷ったら**並べて比較**し、観点ごとの勝ちと理由を残す。これがいちばん強くエージェントに効く | 画面「並べて比較」 |
| エージェント | 監督の指摘が同じ種類で2回続いたら、ルールを提案。承認されたものが全話のブリーフに入る | 画面「ルール」 |

AIのセルフレビューは、監督のレビューと同じ形（観点タグ・範囲・コメント）で残すので、**AIの見立てと監督の見立てのずれ**が並んで見える。ずれが多い観点は、セルフレビューの基準（キャラのノートの「追記」やルール）を足して詰める。

## 4. 使用量を抑える仕組み

**安い順に確かめる。** 高い生成ほど後ろに置き、前の工程で方向を固めてから進む。

| 段 | 使うもの | 費用 | ここで決めること |
| --- | --- | --- | --- |
| 1 | 文章（設計・字コンテ） | 小（LLM のみ） | 尺、動線、画面配置、芝居、感情 |
| 2 | Blender の背景 | 0（自分の PC） | どこから何を撮るか、背景の量と配置 |
| 3 | 9コマ仮Vコン（画像） | 小 | エージェントが想像しているカット、ショットの分け方 |
| 4 | 480p ドラフト（動画） | 中 | 構図・立ち位置・芝居・表情・尺。全部出し切って通しで判断 |
| 5 | ドラフトの作り直し | 中 | 不採用だけ（上限2回、以降は監督へ） |
| 6 | 1080p 本番 | 大 | 採用したドラフトだけ。入力動画をそのまま大きく作り直す |
| 7 | 声・効果音・劇伴 | 小〜中 | 仮（Runway）。後で有料の音源や声優に差し替える |

ツールに入っている歯止め：

- **予算**：**1話5万円**が基準（`config.DEFAULT_BUDGET_YEN`）。超える生成は止まり、優先するものを監督に確認する。最初の数話はテストの回として超えてよい（`episode-set EP01 --test`：止めずに警告だけ）。動画の単価は HAMSTER の実額（15秒で 480p 250円・720p 550円・1080p 1,400円）を1秒あたりに換算して `config.TIERS` に入れてある。9コマシートと音声は仮の値。見直しは [予算と段取りの見直し](予算と段取りの見直し_2026-10-19.md)。
- **見積もり**：`budget-plan EP09` が、ショットの秒数と作り直し率から1話の費用を出す。ショット分けの直後に見て、予算に入らなければ尺かショットを詰める。
- **作り直しの上限**：レビューなしで同じコマを3回作ったら止まる（`TSUKI_MAX_RETRIES`）。迷い続けて使い切るのを防ぐ。
- **本番は採用のあとだけ**：監督の「良い／採用」がないドラフトは 1080p にできない（`promote` / `promote-all` で固定）。
- **LLM の使用量**：ブリーフは要点だけ（読むべきファイルの場所を示し、全文は貼らない）。セルフレビューはドラフトの数フレームを抜き出して見る（動画を丸ごと読ませない）。設計と字コンテは上位のモデル、セルフレビューの一次確認は軽いモデルのサブエージェントに回す。

1話の目安（作り直し率を含む）：仮Vコン 13×1.3 ≒ 17枚、ドラフト 180秒×1.5 ≒ 270秒、本番 180秒×1.1 ≒ 200秒、声・音 約100回。仮の単価での見積もりは EP09（4分版 255秒）で約2.6万円。実際の単価に直したら `budget-plan` で引き直し、EP の実績（`usage`）で作り直し率も直す。

## 5. 編集：Premiere の中で一緒に

- **通しの確認はツールの中**（画面「編集（ライブ）」）：仮Vコン・ドラフト・本番を上映順に通しで再生する。Seedance が付けた音は切り、Runway の仮の声・効果音・劇伴を鳴らす。エージェントの操作は右側にリアルタイムで流れる。
- **編集は Premiere の中のパネルで**（[studio/premiere](../premiere/README.md)）：エージェントがシーケンスを組み、差し替え、マーカーを置く様子を Premiere の画面で見られる。監督が溜め・詰めを手で直して「AIに渡す」と、尺の変更とひとことがツールに戻り、エージェントはそこから続ける。XML の往復はしない。
- **パネルでできない操作は画面操作**（computer use）：エフェクト・色・After Effects など。エージェントを Windows の PC で動かすときだけ。ポスプロの微調整は監督の手を基本にし、エージェントは下ごしらえ（並べる、差し替える、合成用の素材と指示を用意する）を受け持つ。
- **声**：仮の声（Runway）で並べ、声優の声が届いたら差し替える。口の動きが合わないショットは、声優の声を入力にして 1080p を作り直す（`audio-add --role actor` → `promote`）。

## 6. 参照素材の棚

- `asset-add character あかね <設定資料.png>`：キャラの設定資料（三面図・表情集など）。渡された資料をここに入れる。
- `bg-render … --asset-name 店内:A`：Blender の背景。カメラ位置 A〜F ごとに1枚。名前の末尾 `:A` か、カメラ名 `CAM_A` で、字コンテのカメラ位置と自動で対応させる。
- `asset-add layout 店内配置図 <png>`：店内の配置図（文字・矢印は描かないよう指示つきで渡す）。
- `prompt-build` は、そのコマに映るキャラ（台詞の OFF の話者は除く）と、カメラ位置の背景を棚から選び、全話共通の順（背景→配置図→あかね→朔奈→まひる→海凪→暁→おばあ→ステラ→先輩→後輩）で並べる。足りない参照は一覧で出るので、エージェントは監督に伝える。

## 7. 背景：Blender からエージェントがレンダー

- 舞台の .blend に、カメラ位置ごとのカメラ（`CAM_A`〜`CAM_F`、シーン専用は `CAM_S1_xx`）を置く。
- エージェントは字コンテのカメラ位置から、`bg-render` でレンダーする。出力は背景 PNG と、カメラの位置・向き・焦点距離・**画面に映っている物と位置**の JSON。
- JSON の「映っている物」はプロンプトの【このカット】に入り、背景はドラフトの参照画像（@image1）になる。これで構図と配置の崩れ（4話の立ち位置、6話のレモン）を生成の前に防ぐ。

## 8. 脚本が変わったとき

脚本は仮で、変わる前提。設計と字コンテは脚本の版にひもづけ、脚本が変わったら、エージェントが差分を読んで**影響のあるシーンとコマだけ**を挙げ、そこだけ作り直す（未実装・次の段階）。採用済みのコマは、影響がなければそのまま残す。
