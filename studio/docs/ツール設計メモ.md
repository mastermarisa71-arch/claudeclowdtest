# 月灯スタジオ 設計メモ

## 目的

『月灯りスピークイージー』全12話を、**エージェントが作り、監督（人）がレビューする**形で最後まで作り切る。
ツールの価値は「生成できること」より、**人の判断がエージェントに正確に伝わり、次の生成で効くこと**に置く。

## 全体の流れ

```
 vault（正本・決定ログ・制作ルール・脚本）
        │ 読む
        ▼
 ┌─────────────── エージェント（Claude Code） ───────────────┐
 │ 脚本の直し → 設計案 → 字コンテ → 9コマプロンプト → 生成 → 編集 │
 └────────┬──────────────────────────────────▲──────────┘
          │ テイクとして登録（意図・元テイク・直すレビュー）      │ ブリーフ（未対応レビュー・好み・ルール）
          ▼                                                    │
 ┌──────────────────── 月灯スタジオ（DB） ────────────────────┐
 │ cuts / takes / reviews / comparisons / learnings / events │
 └────────┬──────────────────────────────────▲──────────┘
          ▼                                                    │
     レビュー画面（人）：見る・印をつける・並べる・採用・承認 ─────┘
          │
          ▼ 書き出し
     Premiere 用 XML / ffconcat →（After Effects）→ YouTube
```

## 必要な機能

### A. 人がレビューする（中心）

| 機能 | 今 | 内容 |
| --- | --- | --- |
| コマ一覧と尺のタイムライン | ○ | 上映順、尺に比例した帯、テイクの有無・採用・未対応レビューの色分け |
| 範囲つきレビュー | ○ | 画像はドラッグで範囲、動画は再生位置。採用/良い/保留/修正/却下、観点タグ、コメント |
| 並べて比較 | ○ | 2〜4テイクを横に並べ、観点ごとの勝ちと総合の勝ち、理由を残す |
| テイクの系譜 | △ | 元テイクとエージェントの意図は表示。プロンプトの差分表示は未 |
| エージェントの返答を確認 | ○ | 「直った」「まだ」で閉じる／差し戻す |
| ルールの承認 | ○ | エージェントの提案を編集して承認。承認済みだけがブリーフに入る |
| 文書（脚本・字コンテ・設計）へのレビュー | △ | 字コンテのコマへのレビューは可。脚本・設計の段落単位のレビューは Claude Docs のコメントと連携予定 |
| 通し再生でのレビュー | × | 採用テイクを音声つきで通し再生し、時刻でレビュー（次の段階） |
| 動画の注釈 | × | 動画の上にも範囲を描く、区間（in/out）指定 |

### B. エージェントが作る

| 機能 | 今 | 内容 |
| --- | --- | --- |
| ブリーフ | ○ | 読む資料、承認済みルール、未対応レビュー（範囲つき）、比較の好み、最近の流れ |
| 字コンテの取り込み | ○ | 既存 xlsx（版ごとの列の違いを吸収） |
| テイクの登録・生成 | ○ | `take-add` / `generate`。失敗も記録 |
| 9コマシートの切り出し | × | シート画像 → 9コマに等分 → 各コマのテイクへ（e009 の手順を移植） |
| プロンプトの組み立て | × | 共通ブロック＋コマ記述＋参照の添付順を、字コンテとルールから自動で組む |
| 音声 | × | 台詞の抽出 → 声の割り当て → 生成 → 尺合わせ（e009 の audio_plan を移植） |
| 編集の書き出し | △ | V1 のみ。音声トラック・字幕・タイムコード・After Effects（ExtendScript）は次 |

## 実装の方針

- **単純な構成**：Python（FastAPI）＋ SQLite ＋ ビルド不要の JS。Windows のローカル PC で `python` 1つで動く。
- **エージェントは Claude Code**：リポジトリの `CLAUDE.md` と skill（`tsukiakari-studio`）で役割と手順を固定し、操作は CLI。次の段階で同じ操作を MCP サーバーとして出せば、Claude Desktop などからも使える。
- **レビューは構造化して残す**：自由文だけでなく、観点タグ・範囲・比較の勝ちを持つので、エージェントが「どこを・なぜ」を取り違えにくい。
- **ルールは人が承認したものだけ効く**：エージェントがレビューから一般化しすぎるのを防ぐ。承認済みのルールは vault の制作ルールにも書き出す。
- **生成物は git に入れない**：DB と画像・動画・音声は `TSUKI_DATA`（ローカル or 共有ドライブ）。git には設計・プロンプト・計画だけ。

## 段階

1. **骨組み（今回）**：データの形、レビュー画面、CLI、字コンテ取り込み、XML 書き出し。
2. **生成をつなぐ**：HAMSTER の接続、9コマシートの切り出し、プロンプトの自動組み立て、EP09 の 22シートで通しで試す。
3. **通しで見る**：音声つき通し再生、時刻でのレビュー、音声トラックの書き出し、プロンプトの差分表示。
4. **上流の工程**：脚本・設計・字コンテへの段落単位レビュー（Claude Docs 連携）、字コンテの版の比較。
5. **仕上げ**：After Effects 連携、MCP サーバー化、複数人のレビュー（脚本の若林さん、外部レビュアー）。
